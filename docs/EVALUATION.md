# Intent-inference evaluation

## Task

Medication check-in responses are mapped to five user-utterance states:

- `Taken`
- `Refused`
- `Delayed`
- `Confused`
- `Distress`

`NoResponse` is generated by the silence watchdog and is therefore excluded from utterance-classification metrics.

The runtime path first attempts the configured LLM classifier. Invalid JSON, an unavailable endpoint, or a timeout triggers the deterministic lexical baseline.

## Dataset

`app/backend/tests/fixtures/intent_dialogues_100.json` contains 100 synthetic English dialogues, balanced across the five classes at 20 examples per class.

The set is versioned to make regressions visible, but it is not a held-out clinical dataset. It was written to cover common paraphrases and safety-relevant phrases, so its results should be interpreted as test coverage rather than evidence of real-world generalization.

## Metrics

The evaluation harness reports:

- accuracy;
- per-class precision, recall, and F1;
- confusion matrix;
- mean and p95 inference latency;
- whether the configured 85% regression gate is met.

Distress recall has an additional 90% CI floor because missing a safety-related utterance is more costly than an unnecessary escalation in this prototype.

## Reproduce

```bash
cd app/backend
uv sync --locked
uv run python -m benchmark.intent
uv run python -m unittest tests.test_intent -v
```

To evaluate the configured model path as well:

```bash
uv run python -m benchmark.intent --include-llm
```

This requires the model endpoint and corresponding environment variable selected in `config.json`.

## Evaluation roadmap

1. Split future data by speaker to prevent paraphrase and identity leakage.
2. Add ASR corruptions, incomplete sentences, negation traps, and adversarial multi-intent responses.
3. Report confidence calibration, selective accuracy, coverage, and escalation cost.
4. Add out-of-distribution and abstention behaviour.
5. Compare prompts and model versions against the same immutable evaluation manifest.
6. Monitor class balance, drift, latency, fallback rate, and human overrides after deployment.
